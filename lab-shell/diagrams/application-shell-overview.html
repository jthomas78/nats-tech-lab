Phase 1 · Application Shell Design Gate · PROPOSED

Application shell structure and frontend injection

A single Vue host owns the UniFi frame and global providers. Curated metadata declares where independently built frontends contribute; implementation code is loaded only when a route or extension point needs it.

Ownership rules carried into migration

  • The shell owns composition. One AppShell, router, UniFi theme, PrimeVue setup, toast outlet, global locale selection, permission gates, and global error boundaries.
  • Plugins own feature execution. Feature components, namespaced stores, API adapters, watchers, and disposal remain with the independently built remote.
  • Credentials do not collapse. Admin, Tech Lab Operator, and SeaFreight retain their existing PLATFORM and tenant NATS identities and connection lifecycles (BR-AS10).
  • Migration remains gated. This is a proposed Phase 1 architecture; the three current applications move only after the independent remote proof and capability-complete mockups are approved.
