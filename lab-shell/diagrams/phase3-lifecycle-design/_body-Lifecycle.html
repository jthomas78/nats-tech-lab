App Shell · Phase 3 design

Two lifecycle classes

The class is stored on the entry, not inferred. diffRegistry branches on it: a static removal is offered, a dynamic removal is applied.

Static  curated or preloaded — today's semantics, unchanged

registered
Manifest validated, contributions indexed. No code fetched.
↓ first navigation loads the remote
active
No transition out. The status machine has no legal successor state, which is exactly why nothing needs a teardown path.
↓
pendingReload — offered, never applied
Entry removed, or its remote URL moved. The shell shows the banner; the browser's own reload is the only thing that applies it. BR-AS19
Disable takes effect next reload. A static plugin keeps running until then, and the Admin panel says so.

Dynamic  announced by a service — the only class that disposes

announced
Signature verified, origin allowlisted, recorded — and served to no shell. Visible in Admin as pending.
↓ operator enables
registered → active
Indexed live into the running shell. Same loader seam, same at-most-once rule.
↓ unregister, or operator disable
withdrawn — disposed
Scope disposed: routes, nav, extensions, controls, footer items, stores, watchers. Nav item goes at once; the route stops resolving for new navigations.

Health is an overlay, not a state

connected
Backing service present on NATS.
↔
unavailable
Debounced red dot beside the nav item. Contributions stay indexed; nothing is torn down. Clicking shows the inline error panel with Retry.
Disconnect never removes anything. A docker compose restart must not yank a feature mid-session, and a dot that flickers on every deploy trains people to ignore it. Only an explicit unregister or an operator disable withdraws a plugin.

Withdrawn while the user is inside it

In-place tombstone
The occupied view is replaced by a shell-owned panel — this feature was withdrawn, with a link back. The user is never teleported mid-task and nothing unsaved vanishes without explanation.
Consequence for the router: a withdrawn route stays resolvable for exactly one occupant while being removed from the nav and from new navigations. More work than a redirect, and the only option where disposal is deterministic and the user is left in control.
