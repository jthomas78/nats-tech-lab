How a plugin loads — static and dynamic

The two classes differ only in how they arrive and how they leave. From the first navigation onward the load path is byte-for-byte the same code.

8disconnect observed → debounced red dot beside the nav item
9Contributions untouched. A restart or deploy must never yank a feature mid-session — health decorates, it never removes.
—— explicit unregister, or the operator disables it ——
10notify → conditional read → diff finds a removal on a dynamic entry
11withdraw — the plugin's routes, nav items, extensions, controls and footer items are removed. The federated module stays resident; nothing can un-evaluate it.
12If a user is standing on one of its routes: in-place tombstone. The route resolves for that occupant and for no new navigation.
Steps 5–7 of the static sequence are the whole loading story for both classes — pluginLoader owns when and at-most-once, and federation only ever answers “fetch this container, give me this module”. Registration decides what is in the nav; it never decides what is downloaded.
