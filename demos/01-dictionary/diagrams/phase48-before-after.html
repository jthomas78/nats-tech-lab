PHASE 48 · 48a–48j · BR-051 / BR-053 / BR-054 / BR-055 / BR-AC36

Tenant provenance for obs.trace.* — before and after

Phase 48 closed the item ADR-047 amendment A1 deferred: a span's originating account is now established by the NATS server rather than asserted by whoever published it. Fixing that exposed three more defects in the same path — an unbounded bucket, a write that lost spans, and a delivered refusal that closed green.

What changed, by sub-phase
BeforeAfterWhy it mattered
Who says
which tenant48a · 48d · BR-AC36		 Every tenant's obs.trace.> imported bare — once inside PLATFORM, two accounts' spans were indistinguishable. Each import carries a per-tenant LocalSubject remap, arriving as monitor.{tenant}.trace.>. Re-provisioning converges every existing account on each boot, not just new ones. The account boundary is the tenancy boundary in this repo. If provenance is asserted by the publisher, it is spoofable one level down.
Where the
tenant is read48b · 48c · BR-051		 Inferred in the frontend from a hardcoded service-name list, and only ever coarse: PLATFORM or TENANT. Derived positionally from the arrival subject, server-inserted, and stored per span beside the publisher's own document — never merged into it. A trace legitimately spans two accounts, so there is no "the trace's tenant". BR-052 assumed there was and was retired in 48c.
Bucket
size48f · BR-053		 Unbounded — a bare KeyValueConfig{Bucket}, no TTL, no MaxBytes, while its PUBSUB sibling was already capped. 15 min / 8 MiB, from a measured seed run rather than the ADR's estimate, and matched to pubsub-messages exactly. The bucket is the panel's read path, so its size is a page-load cost. Equal windows are what let the two panels cross-reference one incident.
Write
shape48g · BR-053		 Read-modify-write on one merged key: O(n²) bytes, and a lost span whenever two writers overlapped. One idempotent Put per span at trace.{traceId}.{spanId}, joined at read time. The feed's monotonic-merge guard was removed, not ported — a stale snapshot is now a no-op. Diagrammed above. The narrower fix — a revision-CAS Update with retry — closes the race but not the write amplification.
Dedup48g · BR-053 Duplicates left at the server default and inert: no message carried Nats-Msg-Id, so JetStream had nothing to compare. Window set explicitly to 2 min, and natstrace's publish sets Nats-Msg-Id = span id. Both halves are one contract. A dedup window with no message id looks configured and does nothing — the failure mode is silence, not an error.
Error
status48j · BR-055		 A delivered refusal closed the caller-side hop OK, so a failed call rendered green in the middle of a red chain. A reply carrying Nats-Service-Error finishes its span ERROR whichever method the caller used, and the chain reads red end to end. Found by reading 48h's own error run in the panel — the harness had been asserting around the wrong status rather than on it.
How it is
verified48h · 48i · BR-054		 Nothing exercised a multi-hop trace. Every test asserted its own single span; none crossed a service, let alone an account. seed-traces drives a real cross-account, three-span chain — organizations → refdata — in both outcomes, asserting parentage, both services, and per-span attribution. The waterfall's nesting and error rendering had only ever been checked against fixtures it built itself.
