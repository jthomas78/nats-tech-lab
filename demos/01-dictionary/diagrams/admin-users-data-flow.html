Phases 50–52 · ARCHITECTURE-ACCOUNTS "NATS user registry" · BR-AC38–AC41, BR-AC44–AC45, BR-060

Where Users data lives, and how it reaches the panel

The Admin UI's Users panel joins two independent sources in the browser: a Postgres registry of every NATS user this service has ever minted, and a live /connz read from the NATS monitor. The registry is Postgres only — there is no KV bucket behind it.

Implementation notes

  • Postgres, not KV. accounts.users, created in store.go:182; columns public_key (UNIQUE, the natural key), name, account, account_key, kind, status, bearer, source, issued_at, expires_at, activated_at, issuer_key, permissions JSONB. Index users_account_idx (account, name). Deliberately no FK to accounts.accounts.
  • Health reads the JWT, never the connection count. healthOf() at UsersPanel.vue:114 returns exactly four values in this order: pending (status is pending), valid (no exp claim at all), expired (exp in the past), expiring (exp within EXPIRING_MS = 1 hour). A user with zero connections is not unhealthy.
  • No caching anywhere. Every 10 s tick re-requests both sources.
  • The roster is unpaged; /connz is not. ListUsers returns everything and UserListResponse is an envelope leaving room for paging later. /connz paging is passed through as page{numConnections,total,offset,limit} and surfaced as the partial · /connz paged note on the Connected summary card when offset + shown < total — a connection on an unread page counts as zero.
  • NKeys are elided everywhere on screen. elideNKey() in format.js:74 renders [FIRST5…LAST5] at 9px; there is no title attribute carrying the full key (BR-061 is enforced as an absence). The clipboard may carry all 56 characters; the screen may not. copyable is detail-pane-only.
  • Session rows are bounded, not permanent. A session NKey rotates on every browser reconnect, so the table gains a row per connect. Phase 52 replaced the start-up-only pending sweep (SweepExpiredPendingUsers) with a background reaper that subsumes it: SessionReaper (reaper.go) calls Store.ReapExpiredSessions at boot and every ACCOUNTS_REAPER_INTERVAL, deleting session rows more than ACCOUNTS_SESSION_RETENTION past their own expires_at. The table is therefore bounded at mint-rate × retention (BR-AC44, BR-AC45). Because the table is bounded, hide expired in the panel now defaults off (BR-060, amended).
