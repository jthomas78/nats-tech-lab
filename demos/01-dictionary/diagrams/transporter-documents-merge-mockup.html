One Documents surface, with typed depth

A CIPC or bank letter shows the same panel with thinner entries and an audit source tag — those four types are plain CRUD with no stream to replay. The panel says so rather than implying parity.
The audit log becomes per-document history, and this is where Phase 46 lands. Phase 46's GIT certificate change log is this panel, generalized: goods-in-transit entries are reconstructed from the TRANSPORTER stream and tagged event log; the four CRUD types fall back to audit rows. Marking the source is the honest move — it shows the operator which history is replayable and which is merely recorded, instead of flattening two different guarantees into one identical-looking list.

What this design commits to

  • The cover strip is the one place goods-in-transit gets prominence. It answers the real objection to merging — GIT is the only document that can suspend an organization, and a flat list makes it as cheap as a T&C PDF. A strip is a better answer than a tab because it shows derived cover status, which is what the operator needs, rather than certificates they must interpret.
  • Superseded rows are shown, off by default, with a count. This is the one place the two current tabs actively disagree: GIT lists superseded certificates, the Documents tab hides them (BR-TP31). A toggle plus lineage in the drill-in keeps both behaviours available — but it is a business-rule change and needs a decision, not a default.
  • Nothing changes on the backend. GIT stays event-sourced on the profile aggregate, the four shared types stay CRUD. If the operator genuinely cannot tell which is which from this screen, that is a POC result worth recording: the CQRS shape is an implementation concern, not a product one.
  • It should ship as its own component. TransporterPanel.vue is already 2,445 lines; a merged surface belongs beside GitCertificatesTab.vue, not inside it.
