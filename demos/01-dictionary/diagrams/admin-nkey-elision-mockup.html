RULINGS — ALL SETTLED 2026-08-27

  1. Elision length: 5 + 5, as specified. An NKey is 56 characters, all but the leading type prefix (A account, U user, O operator) payload — so ten characters is well past the point of collision for a stack with tens of keys. This is for recognition, not verification, which is what settles the length.
  2. Glyph: literal ... (three periods), not …. DECIDED. Applies everywhere the helper renders.
  3. Copy: in scope, detail panes only. DECIDED. The rule is that a key is never shown in full, not that it can never be obtained — the detail panes are where an operator goes to fetch a key for nsc. Click-to-copy on the elided token puts all 56 characters on the clipboard and none on the screen. Table cells get no copy affordance: the Account and Credential columns are for recognising a row, not for extracting a key.
  4. Tooltips go entirely. Removing title from the Account and Credential cells removes what BR-058 put there — the user NKey on Credential, the full account on Account. Both now live in the cell as elided text, so this is a relocation rather than a loss, but BR-058 must be amended in the same task to say so.
  5. Family column: dropped. DECIDED. Every value would restate the leading token of the string beside it, and the alphabetical sort already groups the families visibly without a gutter announcing it. Single Subject column, sorted. Cheap to add back if the grouping turns out to be missed.
  6. Queue groups and SIDs are out of scope — /connz?subs=true returns bare subject strings. Richer per-subscription objects (sid, queue group, delivered count) need subs=detail, a wire change in observability-service and a bigger payload on every connection row. Flagged as the obvious follow-on, not smuggled in here.
