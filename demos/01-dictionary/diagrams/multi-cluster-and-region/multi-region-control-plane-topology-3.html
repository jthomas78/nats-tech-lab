Global control plane, regional data planes — revision 3

Everything revision 2 said, with the top band rebuilt. Revision 2 drew the global control plane as eight tiles in one flat row, and three of those tiles were not the same kind of thing as the other five: the operator is an offline key, the JWT set is not a process, and the small cluster and database the real services run against were not drawn at all. The band is now three groups — what runs, what is only key material, and the backbone underneath — and the gateway mesh includes the hub. Below the corridor nothing changed. The ten portability rules those tiles obey are written down once, in ADR-054, not in this drawing.

  • Compose has no replica concept, so the R1 gap is invisible locally. shared/jstream/jstream.go never sets Replicas, so every stream is single-copy. A local kind cluster running the real Helm chart is where that gets caught — not Compose.
  • Three NATS servers is not three copies of your data. Servers are a cluster property; replicas are a per-stream property. Set them explicitly for every durable stream and every KV or Object Store bucket that matters.
  • Stream replicas never cross a cluster. Cross-region copies are mirrors or sources — explicit, named and eventually consistent. A gateway carries messages, not replication.

Why there is no tenant stack

Figure 3 draws this. The bullets below are the argument behind it.

  • A tenant is a NATS account, its streams, its KV buckets and its Postgres rows. Zero containers. Nothing in the drawing above is created when a tenant signs up.
  • One stack per tenant does not scale — 500 tenants would be 500 stacks. The industry keeps that shape (a “silo”) for a dedicated price tier and pools everything else, which is what the shared-services band shows. The silo is drawn in figure 3 so it is a priced option rather than a shape we drift into.
  • Pooled and siloed is a per-layer choice, not one platform-wide choice. Here compute is pooled, messaging is a pooled cluster with server-enforced account isolation, and Postgres is pooled with code-enforced row separation. Only the middle one is enforced by something other than us.
  • Tenant sign-up is an API call to the provisioner, not a Git commit. GitOps is right for platform shape — regions, clusters, streams, buckets — and wrong for customer onboarding, which cannot wait for a review.
  • The tenant boundary is the NATS account, and the server enforces it. A container or a Docker network is a weaker boundary that would only duplicate what the account already guarantees.
  • A tenant's placement is a record in the control plane, resolved before routing. There is no silent re-route to another region, so a request that arrives at the wrong cell is rejected rather than served from the wrong side of a border.

The rules behind the tiles live in ADR-054

This drawing shows placement. It does not carry the constraint that produced it. That is written once, in ADR-054 — Portability Rules for Multi-Region Deployment and Integration, and the six rules that decide most of what is above are:

  • Rule 1 — every managed or vendor-specific dependency sits behind a port with at least two working adapters, and the second one has to run in CI. This is why object storage is a port and not a bucket name.
  • Rule 5 — NATS is the portability layer, and the operator NKey is always ours. A provider-held root is not a portability problem, it is a sovereignty problem, and it is irreversible.
  • Rule 7 — data residency beats convenience. The global layer holds a pointer, never a copy. That single sentence decides the billing split and keeps audit at home.
  • Rule 8 — every region keeps serving when the global layer is unreachable, login and token renewal included. resolver: full already delivers this, which is why the JWT tile is trust material and not a service. A global outage must degrade to “no new tenants can be created”, never to “a region stops working”. Every tile added to the management backbone has to be checked against this rule first.
  • Rule 9 — there are three cross-border shapes, and the requirement picks one. A leaf node is one site. A residency requirement is answered by an ordinary regional cell under the one global operator. Only a requirement that reaches access and control earns a separate trust domain. Figure 2 exists because of this rule.
  • Rule 10 — backup, DR and raw telemetry inherit residency. A boundary that only covers the live database is not a boundary.
