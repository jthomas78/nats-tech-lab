Multi-region deployment · discussion sketch (LB-V3-L3-04 context)

Global control plane, regional data planes

The split is by plane, not by place. There is exactly one control plane for the whole platform, because there is exactly one NATS operator and one JWT resolver. A region is a self-contained data-plane cell that can serve every tenant placed in it. A tenant is a logical object inside a cell — an account, its streams, its KV buckets, its rows — never a stack of its own.

  • Compose has no replica concept, so the R1 gap is invisible locally. shared/jstream/jstream.go never sets Replicas, so every stream is single-copy. A local kind cluster running the real Helm chart is where that gets caught — not Compose.
  • Three NATS servers is not three copies of your data. Servers are a cluster property; replicas are a per-stream property. Set them explicitly for every durable stream and every KV or Object Store bucket that matters.
  • Stream replicas never cross a cluster. Cross-region copies are mirrors or sources — explicit, named and eventually consistent. A gateway carries messages, not replication.

Why there is no tenant stack

  • A tenant is a NATS account, its streams, its KV buckets and its Postgres rows. Zero containers. Nothing in the drawing above is created when a tenant signs up.
  • One stack per tenant does not scale — 500 tenants would be 500 stacks. The industry keeps that shape (a “silo”) for a dedicated price tier and pools everything else, which is what the purple band shows.
  • Tenant sign-up is an API call to the provisioner, not a Git commit. GitOps is right for platform shape — regions, clusters, streams, buckets — and wrong for customer onboarding, which cannot wait for a review.
  • The tenant boundary is the NATS account, and the server enforces it. A container or a Docker network is a weaker boundary that would only duplicate what the account already guarantees.
  • A tenant's placement is a record in the control plane, resolved before routing. There is no silent re-route to another region, so a request that arrives at the wrong cell is rejected rather than served from the wrong side of a border.
