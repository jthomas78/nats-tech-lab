Decisions this mockup makes

  • The kind tag appears only when the list is heterogeneous. In state A every visible row is a stream, so a STREAM tag on all six would be pure decoration — the same argument AccountsOverviewPanel.vue already makes for not shipping a permanent "0 slow" tile. Tags switch on the moment either toggle is enabled.
  • The OBJ_/KV_ prefix is stripped once the tag carries it. organizations-docs + an OBJ tag beats OBJ_organizations-docs + the same tag: the rail is 250px, and the name shown is now the one actually configured in objectstore.go. Sorting sinks kv/objstore below streams within each account.
  • Toggles are two independent chips, not a segmented control. These are additive opt-ins layered on always-visible streams, so both-on is a meaningful fourth state. TraceWaterfall.vue's joined .kind-group is right for rest/nats because that is one axis with three states; copying it here would be cargo-culting the wrong idiom.
  • Edge case 1 — collapsed accounts auto-expand on match. Otherwise a filter silently hides its own results behind a collapsed caret. Collapse state is restored when the search clears, so filtering borrows the caret rather than overwriting the user's choice.
  • Edge case 2 — accounts with no match disappear entirely (state C, PLATFORM), with a muted line naming what was dropped. Empty group headers would crowd a 250px rail; a silent disappearance would look like the account had gone away.
  • Counts change shape while filtering — 6 of 23 streams · 2 of 3 accounts — so a filter matching nothing can't be mistaken for a backend returning nothing.
  • Clicking a kv or objstore row still needs a destination. StreamView shows raw messages, which for these is chunk/revision plumbing. Deferred: route kv rows to KvInspector, objstore rows to a read-only object listing. Until then those rows should select but show a "inspect via …" placeholder rather than a misleading message list.
