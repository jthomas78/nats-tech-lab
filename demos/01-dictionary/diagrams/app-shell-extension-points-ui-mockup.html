Where the contribution points are in the UI

Every region the shell owns, drawn on the frame a user actually sees. A plugin fills a target; it never chooses where a target lives and it cannot invent one. Capacities below are the ones the shell declares in declareShellExtensionPoints() and demo-catalog's manifest, as built.

Contribution kinds, and what places them

extensiona named, versioned target — the only kind that can reach a plugin-owned region
shell-controltopbar, right of the breadcrumb — active route only

Actions, commands, settings providers, global search and event-bus messages stay out until a real consumer defines their input and layout.

The rule the picture is making

Targets are {owner}/{region}/v{major}. Context objects are frozen before delivery, so a contributor mutating what it was handed affects neither the host nor a sibling. Owner is not a synonym for shell — number 5 is owned by a federated plugin, and a second plugin contributing into it is the cross-owner case a shell-only proof would miss.
