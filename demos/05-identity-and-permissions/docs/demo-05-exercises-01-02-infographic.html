Let a client in. Then limit what it may do.

The question: can we admit a client while limiting exactly what it may publish and subscribe to? Two NATS users, order-svc (writes orders) and analytics-reader (reads them), on one bare server. Everything below was run in a terminal and re-run as a check script.

00

Two ideas. Keep them apart.

01

Exercise 01 — who gets in?

02

Exercise 02 — the open side

A · before — order-svc lists one side 
publish:   { allow: "orders.>" }
subscribe: (not listed → open)
B · after — order-svc lists both sides 
publish:   { allow: "orders.>" }
subscribe: { deny: ">" }
03

Read a denial in three places

1 · The client What the sender is told 
Permissions Violation
 for Publish to
 "invoices.created"

A subscribe error comes after Subscribing on … is printed. Do not trust the exit code alone.

2 · The server log What the operator sees 
[ERR] "$G/user:order-svc"
 - Publish Violation
 - Subject "invoices.created"

It names the user and the subject. $G is the global account, the only one in this demo.

3 · The delivery What really got through 
listener: 1 message
  from-order-svc
(nothing from the reader)

A silent listener alone proves nothing. A control message that did arrive proves the listener works.
