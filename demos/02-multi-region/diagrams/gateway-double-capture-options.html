Phase 64d · Multi-Region-Plan D11 · open decision

One publish, two copies — and the three ways out

The za/au gateway mesh is up, and a single publish in one cell is stored in both. A JetStream domain protects the API, not the subject space. Below: what happens today, then what each of the three candidate fixes actually changes.

What each option actually changes

  • Option 1 changes the subject. Same account, same gateway, disjoint filters. Cheapest to reason about, most expensive to live with: it spends a design rule we chose on purpose and still leaves two write sides.
  • Option 2 changes the ownership. One writable stream, one write side, a stated one-way copy. It fixes the drift, not the isolation.
  • Option 3 changes the account. Server-enforced isolation, then a mirror where a copy is genuinely wanted. Both NATS and Synadia's own examples combine the two this way.
  • The tension to settle first. An account per region cuts across the recorded decision that a tenant is a marketplace-operating business, not a region — and the account boundary is currently the only thing authenticating anything. Deciding option 3 means reopening that.
  • Nothing is decided yet. The probes were purged and the lab is clean. Phase 64e (three-way replicas) was deliberately not started, because hardening two double-capturing streams would make the wrong shape harder to undo.
