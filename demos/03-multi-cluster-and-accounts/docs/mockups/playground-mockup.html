History

T4 playground

Freeze a region, resume it, or request the meta leader in another cluster. Then watch what the nine servers report, and try a write and a metadata change.

The rig is T4: three clusters of three nats-server processes on this machine, za, au and the hub arb, joined by gateways. All nine vote on JetStream metadata. Each cluster has its own stream, ODOMETER_ZA, ODOMETER_ARB and ODOMETER_AU, with three copies inside that cluster.

What each control does

  • Start rig runs lab/rig-t4.sh up. The service owns that rig and stops it when it shuts down.
  • Attach uses a rig that is already running. The service checks all nine processes first. It never stops a rig it attached to.
  • Freeze turns Dark on: SIGSTOP to the cluster's three processes. This is a clean, total stop. It is not a network partition.
  • Resume turns Dark off: SIGCONT. Restore all frozen clusters does it for every cluster.
  • Request leadership here asks the meta leader to step down in favour of that cluster. NATS can refuse, or elect elsewhere. The page shows the leader it then observed.
  • Publish new writes one message with a new ID. Retry same ID sends the same message again. JetStream drops a copy it already holds and says so.
  • Verify storage reads the stream back and says, for each message ID, present or absent at that time.
  • Try metadata operation creates and deletes a small stream. It needs a meta leader. A stream write does not.
  • Gateway arrows join the panels: arb at the top, za and au below it. Each arrow is one direction, read from the server that dials out. The tag n/3 counts the servers whose fresh reading lists that direction. A dashed arrow, tagged ?/3, has no fresh reading from its own end. A listed gateway is not proof that the far side answers.
  • Client connection picks the cluster the service connects through. The destination stream is set by the panel. So you can publish through au to ODOMETER_ZA.

What the page cannot tell you

  • A monitor that does not answer is not proof that the process stopped, or that quorum is lost. Process state is shown on its own.
  • A missing or stale reading is unknown. It never counts as a vote, and never as zero.
  • Times to agreement are polled every 0.5 s, so each is good to about half a second.
  • What the playground shows is not evidence. Measured results live in REPORT-10.

Start

The control service, from the repo root:
go run ./demos/03-multi-cluster-and-accounts/playground serve
Then open the Playground and press Start rig, or Attach.
