`pricing-service` (`internal/tenants/tenants.go`, 288 lines), `trading-partner-service` (`internal/tenants/tenants.go`, 368 lines), and now `refdata-service` (`refdata/internal/tenants/tenants.go`, Phase 32) each independently implement: discover `.creds` files in a directory, open one `nats.Connect` per tenant, subscribe to `notify.accounts.account.{created,suspended,reactivated}` to provision/teardown connections reactively, close on shutdown. `shipping-service` has the same logic embedded in its larger `internal/rest/tenant.go` (577 lines, plus JetStream/KV provisioning). This is how a browser reaches any of these services directly under its own tenant's NATS account, without going through shipping-service as a relay.

**A real bug already came from the duplication, not a hypothetical one:** the `observability.creds` exclusion (a restricted PLATFORM user that must never be treated as a switchable tenant) was missing from two of the three copies, opening phantom connections that failed with subscription violations — found live via NATS server logs, fixed separately in each file at different times. Included from the start in refdata-service's copy.

**`refdata-service`'s copy is now the fourth — done, not deferred.** Phase 32 (2026-08-17) added `refdata/internal/tenants` + `refdata/internal/browserrpc` (the `api.*` adapter, mounted per tenant connection *and*, additionally, on refdata-service's own PLATFORM connection via `MountPlatformAPI` — see [phase32_refdata_platform_credential](phase32_refdata_platform_credential.md) for why a fourth, PLATFORM-scoped mount was also needed). `refdata/internal/tenants/tenants_test.go` has real coverage against an embedded NATS server (nats.Name assertion, discover exclusion, idempotent ensure/teardown/close) — the other three services' tenant managers still lack this.

**Extraction into a shared `natstenants` Go package is now scheduled: Phase 35 (PROPOSED 2026-08-17, [rest_nats_transport_consolidation](rest_nats_transport_consolidation.md)).** Confirmed by the user ("All three in Phase 35") to bundle three extractions together, since all three hit the identical module-strategy blocker: `natstenants` (this one), `natstrace` (distributed tracing, 5 services), and the `browserrpc` infra reply-tail (`contextFromSubject`/`respond`/`respondError`/`reply`/`responderIdentity`/`responderHeader`, 4 services — handlers themselves stay put). Phase 35.1 makes the module-strategy decision itself (`go.work` vs. shared module + `replace` directives) the first deliverable rather than an unstated prerequisite.
