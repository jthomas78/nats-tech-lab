**Resolved by Phase 35 (2026-08-18) — see [[Main-POC-Plan-ARCHIVE]] for the full extraction record.** The history below is kept because BR-D40 (`BUSINESS_RULES-REFDATA.md`) and the Phase 35 archive entry both point back to it for why the extraction mattered; do not treat anything below as current-state — `refdata/internal/tenants`, `pricing/internal/tenants`, and `tradingpartner/internal/tenants`' old content no longer exist, replaced by `shared/natstenants.Manager[R any]`.

`pricing-service` (`internal/tenants/tenants.go`, 288 lines), `organizations-service` (`internal/tenants/tenants.go`, 368 lines), and `refdata-service` (`refdata/internal/tenants/tenants.go`, Phase 32) had each independently implemented: discover `.creds` files in a directory, open one `nats.Connect` per tenant, subscribe to `notify.accounts.account.{created,suspended,reactivated}` to provision/teardown connections reactively, close on shutdown. `shipping-service` had the same logic embedded in its larger `internal/rest/tenant.go` (577 lines, plus JetStream/KV provisioning). This is how a browser reaches any of these services directly under its own tenant's NATS account, without going through shipping-service as a relay.

**A real bug already came from the duplication, not a hypothetical one:** the `observability.creds` exclusion (a restricted PLATFORM user that must never be treated as a switchable tenant) was missing from two of the three copies, opening phantom connections that failed with subscription violations — found live via NATS server logs, fixed separately in each file at different times. Included from the start in refdata-service's copy. This was the strongest evidence for extracting a shared package rather than leaving the duplication — see BR-D40's Phase 35 amendment.

**What Phase 35 did.** Extracted the shared machinery into `shared/natstenants.Manager[R any]` (generic over each service's per-tenant resource shape), consumed by `pricing-service`, `organizations-service`, and `refdata-service` directly, and by `shipping-service` for connection lifecycle only (its JetStream/KV provisioning stayed local). Every old per-service copy was deleted outright, including their own test files — `shared/natstenants/tenants_test.go` (embedded NATS server) is now the one shared suite every consumer benefits from. `ARCHITECTURE-ACCOUNTS.md`'s "per-tenant connections" section, `BUSINESS_RULES-REFDATA.md`'s BR-D40, and the package's own doc comment were all updated from recommendation/duplication language to implemented-shared-package language in the same phase.
