Architecture model guide · the levels

Five levels, one question each

Each level answers one kind of question. L0 finds documents. From L1 to L4, each level adds detail to one subject in the level above. The levels organise architecture information. They are not a delivery sequence: write the level that a question needs. Sheet 2 follows one fictional example through L1 to L4.

Choosing a level
  • To find a document, start at L0.
  • To learn what the system is, start at L1.
  • Too much detail for a level? It belongs one level lower, under the subject it details.
  • A concern that crosses several parts gets an L3 view, not more detail in L2. L3 explains how it works; L4 specifies one design in it precisely.
  • Not every L3 needs an L4. Add one when someone must build it.
  • Not a delivery sequence. Write the level a reader needs. A lower level is added when someone needs that detail.
Beside the levels, not levels
RequirementsOne register per document. Each requirement has an ID. The view traces its content back to a requirement, and each requirement to the view that addresses it.
ADRs — decision recordsOne decision log with one number sequence. A decision can govern documents at any level, and one decision can govern several documents.

Document readiness and decision status
Document readiness — can I read it?
PLANNEDListed in the atlas. Nothing to read yet. DRAFTReadable and open to review. Not accepted, or not complete. AVAILABLEDrawing and print edition match and passed validation. SUPERSEDEDKept for history. Points to its replacement.
Decision status — is it settled?
ADR PROPOSEDThe decision is written down, not yet accepted. ADR ACCEPTEDThe decision of record. If a view disagrees, the view is corrected. DIRECTIONALA dated first-pass position. Each provisional item is marked.
Readiness is not approval. A document can be AVAILABLE and directional: ready to read, with some choices still open.
