Two Axes That Cross — Trust Against Placement

Who a tenant is, what sits inside one, and in which cells that tenant is allowed to exist. The NATS trust hierarchy names who and carries no geography; the placement hierarchy names where and carries no identity. They cross; neither one contains the other. This is a directional document: a first-pass position recorded so the platform can move, not a settled decision, stated as at 17 September 2026. Nothing on this sheet is built — the lab runs one server in one region. Subjects, streams and grants belong to LB-V3-L3-05; residency and border rules belong to LB-V3-L3-08; claim text and schemas belong to L4.

SCOPE

One question. Who is a tenant, and in which cells may that tenant exist? What runs inside one cell is sheet 2.

DIRECTION

Directional. A first pass as at 2026-09-17 so work can start. Not a decision, and not compliance evidence.

AXES

Two hierarchies. Trust names who. Placement names where. Neither one contains the other.

ACCOUNT

A tenant is one account. It keeps one identity in every cell it is permitted to use.

CELL

A cell is one region's complete runtime. It is a place, and it names no tenant.

ORG

Organisations live inside an account. A role or a membership never makes a second NATS account.

DOMAIN

A JetStream domain marks a cell. It is not a tenancy boundary; the account is.

GRID

Read a row for an account and a column for a cell. A red square is a refusal, not a gap.

SYSTEM

The system account administers servers only. It carries no business traffic in any cell.

OPEN

Every amber tile needs a named owner. Six open items are listed in the L3-01 register.

Inside One Square — Which Services Run Where, and Whose Credential They Hold

One cell on sheet 1 is one square in the grid. This sheet opens that square. The cell owns the runtime and names no tenant. A service replica runs in the cell and borrows a short-lived user credential to act for one tenant account. Every durable record that replica writes lands inside that account. This is a directional document as at 17 September 2026, except the bottom band, which is measured in the demo 03 lab. Service responsibilities belong to LB-V3-L2-01; subjects and streams belong to LB-V3-L3-05; packaging and scaling belong to LB-V3-L3-12.

SCOPE

One square, opened. What runs inside one cell, and whose account owns what it writes.

DIRECTION

Directional as at 2026-09-17, except the bottom band. That band is measured.

CELL

The cell owns the machinery. Ingress, NATS, workflow and stores exist once per cell.

REPLICA

A replica is a place-thing. It runs in a cell. It borrows a user; it never owns an account.

CREDENTIAL

One connection carries one user credential. Two accounts means two connections.

DATA

Streams, KV, Postgres and documents are tenant-owned and stay inside the cell that holds them.

KV

A KV bucket is really a stream. So it obeys every account rule a stream obeys.

HA

Three NATS servers is a logical minimum, not a sizing number. Sizing is L4.

MEASURED

Only the four solid tiles are measured. Everything else is proposed or open.

OPEN

L3-01-O01 is the one to answer first. It changes how every service is deployed.

Which Account Does Each Service Connect As

Sheet 2 says a replica borrows a user credential. This sheet says whose. Every service named on LB-V3-L2-01 is a row; the three account types from sheet 1 are the columns. One connection sees exactly one account, so a service that needs two accounts needs two connections. This is a directional document as at 17 September 2026. Nothing here is built. The service names are carried down from LB-V3-L2-01 and are not restated or extended; subject and grant text belongs to LB-V3-L3-05; permission claims belong to LB-V3-L3-09 and L4.

SCOPE

One question. Whose credential does each service hold? Sheet 2 asks it; this sheet answers it.

DIRECTION

Directional as at 2026-09-17. Nothing on this sheet is built, and no V3 ADR exists.

SOURCE

Every service name is carried down from LB-V3-L2-01. This sheet adds no service of its own.

RULE

One connection sees one account. A service that needs two accounts needs two connections.

SYSTEM

Only NATS provisioning connects as $SYS. It pushes account claims. That is the whole job.

CONTROL

The control plane is platform-shaped. It owns records about tenants, not records of a tenant.

DOMAIN

The domain plane is tenant-shaped. All eight rows have the same answer, which is the point.

IMPORT

An import is read-only and renamed on arrival. Demo 03 measured that. It is the only door.

REFUSED

A red square is a decision. A domain service must never hold administrative rights.

OPEN

L3-01-O07 and L3-01-O08 are raised by this sheet. Both need architecture to confirm.
