## One-paragraph version, if that's all you need

Dictionary/reference data (currencies, ports, hazard classes, UI copy, and so on) got pulled out of the shipping backend's event-sourced world entirely, because **nothing ever needs to replay a lookup value's history** — only its current value matters. That's now `refdata-service`: its own Go service, its own Postgres schema, plain CRUD, no event log. It distributes reads through a versioned NATS KV cache (`refdata-{context}`) rather than making every consumer hit Postgres or a REST call — the shipping backend reads that cache directly via `internal/refdataconsumer`, falling back to REST only on a cache miss or version mismatch. It's genuinely a separate service (own container, own schema, zero Go dependency on the shipping backend), proven live via Docker, not just designed on paper. Multi-tenancy, configuration data, and UI theming are named as real gaps, not silently missing — see [[4. Outstanding POC Tasks]].
